# 🎾 최강씨씨씨C조!!!! 🎾

C팀 8명의 복식 20경기를 준비하는 모바일 전략 페이지입니다. `선수 정보` 탭에서 A·B·C·D조 전체 선수 명단을 보고 선수를 선택해 C조의 경기 선호 또는 상대 선수의 관찰 키워드를 확인·수정합니다. `C조 전략` 탭에서 전략별 페어와 출전표를 보고, `상대 페어 분석` 탭에서 우리·상대 페어를 따로 선택합니다.

대상 저장소: https://github.com/gbkchee/team-c-victory

배포 후 기본 주소: https://gbkchee.github.io/team-c-victory/

- 밸런스형 / 필승카드형 / 체력안배형 선택 후 바로 아래에 페어 구성·출전 경기 수 표시
- 밸런스형 안에서 기본 조합 / 파트너 교차 / 새 페어 조합의 3안 비교
- 시간을 행, 1~4코트를 열로 구성한 공식 출전표. 각 경기 칸에 우리 선수 두 명 / vs / 상대 조 표시, 출전표에서 분석 탭으로 이동
- 별도 분석 탭에서 C조 2명 + 상대 A/B/D조와 선수 2명 선택 후 운영·공략 결과 표시
- 두 페어의 최신 선호·키워드를 반영한 공략, 기존 77개 상대 조합의 시트 메모 참고
- 현재 탭·전략·밸런스안·우리 페어·상대 조와 페어 선택을 링크로 공유
- A·B·C·D조를 세로로 배치한 선수 리스트, 등급순·가나다순 정렬, 선수 선택 시 편집 팝업
- C조: 선호 포지션, 게임 스타일, 요즘 자신 있는 플레이, 파트너에게 바라는 역할, 경기·휴식 선호 선택 및 나의 플레이 특징 입력
- C조 특징은 본인이 키워드를 직접 입력하거나 빠른 추가 버튼으로 선택하고 삭제 가능. 최대 20개·각 40자, 분석 화면의 우리 페어 카드에도 표시
- 자신 있는 플레이·파트너 역할은 복수 선택, 점수 없이 입력
- A·B·D조: 포잡이·백잡이 성향, 공격형·수비형·올라운더 스타일, 강점·약점·특징 키워드
- 상대 키워드는 기존 시트 기록을 초기 표시하고 자유 입력·빠른 추가·삭제 지원
- 포티 4️⃣·써티 3️⃣·러브 🫶 이모지는 배경색 없이 표시
- [대회 공식 규정 PDF](rules.pdf)

선수별 입력값은 각자의 브라우저에만 저장됩니다. 다른 기기나 팀원과 자동으로 동기화되지 않으며 공유 링크에도 포함되지 않습니다.

[선수 프로필·추천 기능 설계](FEATURE_SPEC.md)에 공동 저장, 자동 페어 추천, 상대 공략, AI 갱신의 요구사항과 현재 구현 범위를 정리했습니다. 현재 편성은 밸런스형 3안, 필승카드형, 체력안배형으로 총 5안이며 선택 정보로 자동 재편성되지는 않습니다. 분석 탭은 최신 우리 선수의 자신 있는 플레이·파트너 역할·휴식 선호와 상대 키워드를 함께 반영하는 규칙 기반 운영 제안을 표시합니다. 출전표 자동 추천과 실제 AI 호출은 아직 연결되지 않았습니다.

## GitHub Pages 배포

### GitHub CLI로 업로드와 배포를 한 번에 실행

GitHub CLI에서 `gbkchee` 계정으로 로그인한 뒤, 이 저장소의 폴더에서 일반 Mac 터미널로 실행합니다.

```sh
bash deploy-github.sh
```

스크립트는 대상 저장소와 인증을 확인하고 `main` 브랜치를 업로드한 뒤 GitHub Pages를 GitHub Actions 방식으로 설정합니다. 현재 커밋의 검증·배포 워크플로가 성공하고 실제 페이지가 응답하는 것을 확인하면 공유 주소를 출력합니다. 진행 중 오류가 발생하면 중단합니다.

### 빌드된 파일을 웹사이트에서 업로드하는 경우

`team-c-victory-pages.zip`을 압축 해제하고 그 안의 7개 파일을 저장소 최상위에 업로드합니다. ZIP 파일 자체나 압축 해제한 폴더를 올리는 대신 `index.html`이 저장소 최상위에 위치하도록 합니다.

저장소 **Settings → Pages → Build and deployment**에서 **Source: Deploy from a branch**, **Branch: main**, **Folder: / (root)**를 선택하고 **Save**를 누릅니다. 배포 완료 후 **Visit site**로 접속합니다. 이 방식은 GitHub Actions 워크플로 파일을 직접 업로드할 필요가 없습니다.

### 소스와 자동 배포 워크플로를 업로드하는 경우

1. GitHub에 공개 저장소를 만들고 이 폴더의 파일을 `main` 브랜치에 업로드합니다. `.github/workflows/deploy.yml`도 포함합니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 설정합니다.
3. **Actions**에서 배포 워크플로의 완료를 확인합니다. 업로드 후 Pages 설정을 켰다면 **Run workflow**로 다시 실행할 수 있습니다.
4. **Settings → Pages → Visit site**에서 실제 웹페이지 주소를 확인하고 팀원에게 공유합니다.

이후 `main` 브랜치 변경 시 출전표 검증, 빌드, 배포가 자동으로 실행됩니다. 별도 npm 패키지 설치가 필요하지 않습니다. GitHub Pages의 저장소 하위 경로에서도 동작합니다.

## 로컬 실행 및 검증

Node.js 22 이상과 Python 3을 사용합니다.

```sh
npm test
npm run build
npm start
```

브라우저에서 `http://localhost:8000`에 접속합니다. `dist/`에는 실제 배포에 사용하는 7개 파일이 생성됩니다.

검사는 모든 전략의 C1~C20 경기 번호, 전원 5경기 출전, 동시간 중복 출전, 금지 조합, 공식 20경기의 코트 배정, 시트 메모 77개, C조·상대 프로필 분리, 기존 입력 이관, 특징 저장·중복 제거·입력 제한, 금지 페어와 두 페어에 따른 공략을 확인합니다.

기존 포지션·게임 스타일은 의미가 같은 항목에만 이어 사용하며 상대의 강점·약점·특징 키워드도 유지합니다. 이전 숫자 점수를 자신 있는 플레이로 변환하거나 C조 약점으로 표시하지 않습니다. 이전 localStorage 기록은 백업으로 남기고 새 입력은 별도 프로필 키에 저장합니다.

## 경기 운영

- 경기당 복식 2명, 동시간 2경기는 서로 다른 4명 출전.
- 출전 선수는 경기 10분 전까지 제출하며 양팀 제출 후 공개. 제출 후 원칙적으로 선수 변경 불가.
- 러브급 선수끼리 출전 불가.
- 5:5는 타이브레이크 없이 종료하며 양팀 모두 5점을 누적.
- 팀 순위는 전체 게임 득점 합, 승리 경기 수, 팀원 총 나이 합 순.
- 경기 시작 시간은 진행 상황에 따라 변동 가능.

공개 선수 특성은 제공된 전력분석 시트와 신장 정보를 근거로 합니다. 자료가 없는 항목은 정보 없음으로 표시합니다.
