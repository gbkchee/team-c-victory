# 🎾 최강씨씨씨C조!!!! 🎾

C조 8명의 복식 20경기를 준비하는 모바일 전략 페이지입니다. GitHub Pages는 화면을 배포하고 Firebase는 팀원이 입력한 정보를 공유합니다.

저장소: https://github.com/gbkchee/team-c-victory

공유 주소: https://gbkchee.github.io/team-c-victory/

## 사용할 수 있는 기능

- **입장 화면**: 흰 배경·블루 도트 테두리 안에 작은 정면 미니미 두 명이 코트에서 랠리하는 장면과 **코드 입력** 여섯 칸, **입장하기**를 표시합니다. 코트와 입력 영역을 위로 모으고 별도 질문 문구는 두지 않습니다. 코드가 맞아야 앱 파일과 공유 저장소를 불러오며 직접 링크의 탭·선수 선택도 유지합니다.
- **선수 정보**: 공식 31명 명단과 등급. 모바일은 선수별 전체 화면 편집, PC는 팝업으로 엽니다. C조는 여섯 가지 경기 선호, 상대 조는 특징·성향·공격 패턴·어려워하는 상황을 입력합니다.
- **공용 키워드**: 우리팀 특징과 상대팀 추가 특징은 같은 추천 목록을 사용하며 직접 등록한 특징도 양쪽에서 함께 선택·삭제합니다. 상대 공격 패턴과 어려워하는 상황은 종류별로 공유합니다. 선수별 특징 또는 상대 키워드는 최대 20개, 항목당 40자입니다.
- **페어 조합**: 자유 조합(기본)·일부 고정 중 선택하면 1안 강강 조합·2안 리턴 자리 추천부터 서로 다른 최대 5개 조합을 이전·다음으로 비교합니다. 모든 페어는 1경기씩 출전하며 일부 고정은 최대 20개 지정 페어를 각각 한 번 포함합니다. 지정 페어는 선수를 공유할 수 있습니다(선수당 최대 5개). 편집 팝업에서 경기 칸을 끌어 다른 경기와 교환하고(모바일은 길게 누른 뒤 이동) 초안을 확정·저장합니다. 경기 클릭 편집과 상대 입력은 제공하지 않습니다. 자동 추천은 모든 선수의 연속 출전·휴식을 최대 2타임으로, 각 시간대까지 누적 출전 횟수 차이는 최대 1경기로 분산합니다. 자동 추천은 경기·휴식 선호를 공통 분산 조건 안에서 참고하고 상대 조별 1~2경기로 배치합니다. 수동 교환은 동시간 중복 출전만 차단하고 연속 3경기 이상은 선수 이름 옆 💦로 경고하며 적용·저장을 허용합니다.
- **선수별 제안**: 추천 조합마다 C조 8명의 카드를 모두 표시합니다. 각 카드에는 실제 경기 수·파트너와 포·백 제안이 있고 이름을 누르면 전체 경기 정보를 확인합니다.
- **추천 출전표**: 최신 선호를 반영하며 공식 20경기의 시간·코트를 유지합니다. 전원 5경기, 동시간 중복 출전 없음, 러브끼리 페어 금지를 검사합니다.
- **팀 확정표**: 선택한 추천안을 팀 공통 출전표로 저장합니다. 선수 정보가 변경돼도 확정표는 유지하며 다른 팀원의 동시 확정은 충돌로 안내합니다.
- **상대 페어 분석**: 상대 조와 두 선수를 선택한 뒤 **분석하기**를 누르면 한눈에 보기와 주의할 점·대응방안·공략할 상황을 표시합니다. AI가 연결되어 있으면 Gemini 분석을, 연결되지 않았거나 호출에 실패하면 기본 관찰 요약을 제공합니다. 기본 요약은 미리 조사한 복식 자료 10개와 대응 규칙 24개를 사용하며 참고 출처를 제공합니다. 페어나 관찰 기록을 바꾸면 결과를 숨기고 다시 분석해야 합니다.
- **공유 링크**: 탭·전략·운영 방식·고정 페어·분석 선택을 링크에 저장합니다. 선수 프로필은 링크에 담지 않습니다.

선호를 실제 기술 능력이나 승률로 바꾸지 않습니다. 강강 조합은 공식 등급과 선호를 참고한 주력 페어 제안입니다. 미입력은 약점으로 해석하지 않습니다. 상세 동작은 [기능 설계](FEATURE_SPEC.md), 조사한 자료와 적용 범위는 [복식 참고 자료](TACTICS_REFERENCE.md)에 정리했습니다.

## 실행과 검증

Node.js 22 이상과 Python 3을 사용합니다. 정적 페이지와 자동 검증에는 패키지 설치가 필요하지 않습니다.

```sh
npm test
npm run build
npm start
```

브라우저에서 `http://localhost:8000/index.html`을 엽니다. 입장 코드가 맞으면 같은 주소에서 기존 선수 정보 화면이 열립니다. `file://` 미리보기나 소스 폴더 주소 대신 이 로컬 앱 주소를 사용합니다. `index.html`을 파일로 직접 열면 Firebase와 Worker가 정상 동작하지 않을 수 있습니다. 빌드 결과 `dist/`에는 화면 파일·Worker·Gemini 연결 코드·원본 SVG·공식 규정이 포함됩니다. Gemini API 비밀 키와 관리자 도구는 포함하지 않습니다.

자동 검증은 공식 일정, 자유·일부 고정 운영 방식과 추천 전략, 무작위 선호 조합, 데이터 이관, 두 기기 동기화 모형, 미전송 입력의 새로고침 복구, 구독 오류 후 재연결, 동시 편집·확정 충돌, 참고 자료 연결, AI 캐시·한도·실패·늦은 응답, 초기화 범위를 확인합니다. DOM/Firestore 모형을 사용하므로 실제 렌더링·Firestore 규칙·서비스 연결은 배포 후 [실제 서비스 검증](SERVICE_VERIFICATION.md)을 따라 확인해야 합니다.

인트로 진입 시 화면 자체에 초점을 두어 키보드가 자동으로 뜨지 않으며, 입력칸을 누르거나 Tab으로 이동하면 코드를 입력할 수 있습니다. 코드는 입력 즉시 점으로 가려 마지막 글자도 표시하지 않습니다. 코드가 맞으면 앱 파일을 동시에 내려받고 의존 순서대로 실행해 입장 대기를 줄입니다. 공유 저장소 연결은 메인 화면이 열린 뒤 진행합니다.

입장 코드는 `access-gate.js`에 SHA-256 해시로만 설정하고 브라우저에 저장하지 않습니다. 잘못된 코드나 덜 입력한 상태로 입장하면 앞쪽 미니미가 넘어졌다가 일어나며, 그동안 랠리는 잠깐 멈춥니다. 새로고침 시 다시 입력하며 입장 후에는 입장 화면의 랠리를 중지합니다. 메인 헤더는 여덟 미니미를 한 줄로 표시하고 각자의 공 바운스·서브 동작을 재생하며, 모든 탭에서 제목 크기와 헤더 배치를 동일하게 유지합니다. 동작 줄이기 설정에서는 랠리를 멈추고 오류 시 넘어진 정지 자세만 잠시 표시합니다. 정적 웹의 진입 화면이므로 공개 파일이나 Firestore에 대한 직접 접근 권한을 제한하는 서버 인증 기능은 아닙니다.

승인된 imagegen 시안은 `assets/entry-minimi.png`에 보관하며 SVG에서 화면 구성·캐릭터를 재사용합니다. 문구와 입력·입장 버튼은 실제 텍스트와 폼으로 덧씌워 구성합니다. 도트 글씨는 로컬에 포함한 [Neo둥근모](https://github.com/neodgm/neodgm-webfont)를 사용하며 폰트 라이선스를 `assets/neodgm-LICENSE.txt`에 포함합니다.

## 배포와 데이터 초기화

1. [Firebase 연결 안내](FIREBASE_SETUP.md)대로 최신 Firestore 규칙을 먼저 게시합니다.
2. 사용자가 `main` 브랜치를 원격에 푸시합니다. GitHub 저장소 **Settings → Pages → Source: GitHub Actions**로 설정합니다.
3. `.github/workflows/deploy.yml`이 자동 검증·빌드·Pages 배포를 진행합니다.
4. AI를 사용할 때는 안내 문서대로 Spark 요금제를 유지하고 Firebase AI Logic·App Check를 설정합니다. 키 설정이 막혀 있어도 기본 공략·선수 입력·페어 추천은 동작합니다.

기존 `deploy-github.sh`로 업로드·Pages 설정을 진행할 수도 있습니다. 이번 작업에서는 원격 푸시와 실제 서비스 배포를 수행하지 않았습니다.

테스트 선수 입력만 초기화하고 공용 키워드를 보존하는 관리자 도구도 제공합니다. [초기화 절차](FIREBASE_SETUP.md#테스트-선수-입력-초기화)를 참고하세요. 빈 서버 프로필을 남겨 오래된 브라우저 입력이 다시 이관되지 않게 합니다.

## 디자인과 대회 규정

[지정 Figma 전체 화면](https://www.figma.com/design/2Y070IdVZKJyqQldInTYnG/Untitled?node-id=0-1)의 선수 목록·페어 조합과 최신 모바일·PC 편집·상대 분석 상태를 적용합니다. 색상은 #023047을 중심으로 사용하며, 디자인의 예시 이름은 실제 공식 명단으로 표시합니다. 원본 SVG는 `assets/`에서 제공하며 등급은 배경 없는 4️⃣·3️⃣·🫶로 표시합니다.

[공식 규정](rules.pdf)에 따라 러브끼리 출전할 수 없고, 선수는 경기 시작 10분 전까지 제출합니다. 양팀 제출 후 공개하며 제출 후 원칙적으로 변경할 수 없습니다. 5:5이면 종료하고 양팀에 5점을 누적합니다. 팀 순위는 총 게임 득점 합 → 승리 경기 수 → 팀원 총 나이 합입니다.

**전원 5경기는 이 프로젝트의 운영 조건입니다. 공식 규정 PDF의 명시 조건과는 구분합니다.** 출전표는 준비용 제안이며 실제 제출은 팀에서 결정합니다.

팀 출전표 팝업은 공식 40경기(12개 시간대)를 표시합니다. C조 예정 편성과 실제 출전 기록은 분리되며, 각 경기를 눌러 양팀 기록을 각각 저장·삭제합니다. 입력된 기록에 따른 남은 페어 후보가 5개 이하일 때만 목록을 표시합니다. 미입력 경기 수를 함께 표시하며 A·C·D조는 선수당 최대 5경기, B조는 전원 최대 6경기입니다.
